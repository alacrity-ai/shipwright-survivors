# Galaxy Map System

The **Galaxy Map** provides a fully interactive, **3D navigational interface** for selecting missions and locations within _Shipwright Survivors_.  
It renders planetary systems as **rotating, lit 3D spheres** (via WebGL1), supports **hover scaling**, **click-based selection**, and **smooth camera zoom transitions**, and integrates with mission progression.

---

## Overview

The Galaxy Map consists of three primary layers:

1. **Controller Layer** (`GalaxyMapController`)
    
    - Handles all **input, state, and interaction logic**:
        
        - Raycasts from mouse position into 3D space.
            
        - Tracks hovered and selected planets.
            
        - Manages **hover scaling animations** (via per-location state interpolation).
            
        - Commands the camera to **zoom to and orbit around** selected locations.
            
        - Delegates rendering to `GalaxyMapRenderer`.
            
2. **Rendering Layer** (`GalaxyMapRenderer`)
    
    - Responsible for **drawing planets**:
        
        - Uses shared sphere geometry (`createSphere`) for all locations.
            
        - Applies **rotation animation** per planet.
            
        - Implements **per-fragment lighting** (diffuse + ambient).
            
        - Colors and alpha-modulates planets based on **unlock status** and selection.
            
        - Uses the `GalaxyMapCamera`’s matrices for projection and view.
            
3. **Camera Layer** (`GalaxyMapCamera`)
    
    - Smoothly transitions between **default overview** and **focused zoom-in** states.
        
    - Maintains `position` (camera location) and `target` (look-at center).
        
    - Uses **lerped interpolation** to avoid abrupt camera snaps.
        
    - Reverts to overview mode when no planet is selected.

## Interaction Flow

1. **Mouse Hover**
    
    - Each frame, the `GalaxyMapController` converts the 2D cursor position into a 3D ray using `screenToWorldRay`.
        
    - It tests this ray against every planet using `raySphereIntersect`.
        
    - The **nearest intersected planet** (if its mission is unlocked) becomes the current hover target.
        
    - Its `targetScale` is increased by `HOVER_SCALE_MULTIPLIER` (default 1.2×), creating a **pulsing enlarge effect**.
        
    - Previous hovered planets reset back to their baseline scale.
        
2. **Mouse Click**
    
    - On left click:
        
        - If a planet is hit by the cursor ray and its mission is unlocked, it becomes the **selected location**.
            
            - The camera transitions toward it via `GalaxyMapCamera.focusOnLocation`.
                
            - A selection sound is triggered.
                
        - If no planet is clicked, the map **resets to default view** via `GalaxyMapCamera.resetView`.
            
3. **Camera Update**
    
    - Each frame, `GalaxyMapCamera.update()` interpolates the `position` and `target` vectors toward their respective `targetPosition` and `targetTarget` using a tunable `moveSpeed`.
        
    - This results in **smooth zoom and pan** toward or away from planets.
        
4. **Rendering Pass**
    
    - The `GalaxyMapRenderer`:
        
        - Builds view/projection matrices based on camera state.
            
        - Sets up lighting uniforms (directional + ambient).
            
        - Iterates through all planets:
            
            - Composes a **model matrix** (translation, rotation, scaling).
                
            - Chooses color and alpha based on **unlock/selection state**.
                
            - Issues a draw call using the shared sphere geometry.
                

---

## Key Modules

- **`GalaxyMapController`**  
    The central orchestrator for input handling, hover/selection state, and animation.  
    Relies on:
    
    - `screenToWorldRay` and `raySphereIntersect` (for hit detection).
        
    - `missionUnlocked` (to gate interactions).
        
    - `audioManager` (for hover/click SFX).
        
- **`GalaxyMapRenderer`**  
    Performs all **WebGL1-based planet rendering**:
    
    - Loads shaders (`defaultShaders.ts`).
        
    - Uses reusable sphere buffers (generated by `createSphere`).
        
    - Implements **lighting** (per-fragment diffuse + ambient).
        
    - Manages planet color, scale, and alpha.
        
- **`GalaxyMapCamera`**  
    Encapsulates **camera state and transitions**, providing smooth zoom to selected planets or a return to the overview.
    
- **Helpers & Utilities**
    
    - **Raycasting**: `screenToWorldRay`, `raySphereIntersect`.
        
    - **Math & Transforms**: `matrixUtils`, `vectorUtils`, `lookAt`.
        
    - **Geometry**: `createSphere`.
        
    - **Registry**: `GalaxyMapRegistry` and `PLANETARY_LOCATIONS` for defining all planets.
        

---

## Data Model

Each planet is a **`LocationDefinition`**:

```
interface LocationDefinition {
  id: string;
  name: string;
  position: Vec3;         // World-space position in the map
  scale: number;          // Base radius (before hover scaling)
  color: Vec3;            // RGB in [0,1] for planet shading
  rotationSpeed: number;  // Rotation speed (radians per second)
  missionId: string;      // Links to mission unlock state
}

```

All locations are stored in `GalaxyMapRegistry`, populated from `PLANETARY_LOCATIONS`.

---

## Runtime Behavior

- The system runs continuously during the **Galaxy Map scene**:
    
    1. `GalaxyMapController.update()` runs every frame:
        
        - Updates hover scaling and camera transitions.
            
        - Detects clicks and adjusts selection.
            
    2. `GalaxyMapController.render()` calls `GalaxyMapRenderer` to draw all planets with correct transforms.
        
    3. Selection and camera state persist until the player exits the scene or chooses a mission.
